# Default design taste

Observed from the reasoning behind one personal site. Weigh these as taste
to raise against the project at hand, not as a checklist; another project
can clear the bar while looking nothing like that site. A taste file of
your own replaces this one whole; the skill's Input section says how to
name it.

- Personality carried by typography and content, not decoration. A
  terminal/dark theme was too much personality; a plain minimalist layout
  too generic; the accepted direction sat between them.
- One accent used sparingly, never as a dominant block. The site lists
  where its accent colour may appear (role line, intro rule, avatar tile,
  call to action, links) and has no accent-coloured background sections.
- Template patterns are rejected for a stated reason, not by default: skill
  chips went because naming a technology beside the role that used it
  grounds the claim; a sidebar contact block went because it made the site
  read as a resume document; anchor nav went because the page is short and
  removing it reads as more confident.
- Large, offset display type for the name and an asymmetric hero, over the
  small-centred-text pattern that makes minimal sites read as templated.
- Monospace for dates, the role line and meta labels; system sans for body
  and headings.
